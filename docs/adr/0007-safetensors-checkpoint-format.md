# Checkpoints: safetensors instead of pickle, split into model/optimizer files

Checkpoints (`train.py:save_checkpoint`/`load_checkpoint`) were pickle, which is unsafe to load later (arbitrary code execution) and brittle across Python/JAX versions -- a real problem for artifacts meant to be reloaded for eval, resumption, and cross-variant comparison well after the run that produced them. We switched to safetensors: `nnx.to_pure_dict(nnx.state(...))` is flattened to a flat tensor-name dict via `flax.traverse_util.flatten_dict`/`unflatten_dict` (with a str<->int key-normalization step, since optax's tuple-indexed state produces integer dict keys that `traverse_util` can't join into a path string).

Each checkpoint step is written as **two files**, `step_N.model.safetensors` and `step_N.optimizer.safetensors`, not one merged file. This was a deliberate revision of an initial "preserve the exact directory structure" framing: a single merged file would have been closer to the old pickle layout, but AdamW's optimizer state (m and v moments) is roughly 2x the size of the model's own params, and per ADR 0006 this project already hit a hard GPU memory ceiling once. ADR 0005's instrumentation pass and the eventual baseline/KDA/hybrid comparison both mean loading trained weights *without* optimizer state is the common case (eval, attention capture, cross-variant weight comparison), not the exception -- splitting the files means that path never pays for optimizer arrays it doesn't need. The split costs little: keys are already namespaced (`model.*` vs `opt_state.*`), so producing two files instead of one is a filter, not a redesign.

The training step count is written to **both** files' safetensors header metadata (a string->string dict, no sidecar file), not just the optimizer file. Step is logically training-loop/optimizer state, but a model-only load -- exactly the load path the two-file split exists to make cheap -- still needs to answer "which step is this?" without opening the optimizer file. The redundancy is one string written twice; the alternative (step only in the optimizer file) would force every model-only consumer to load optimizer state anyway just to read a number, defeating the split.

`save_checkpoint`/`load_checkpoint` take a single extensionless base path (e.g. `checkpoint_dir / f"step_{step}"`); the two safetensors filenames are derived internally so callers still pass one path and the two-file convention lives in one place. `load_checkpoint` itself always loads both files (it exists for training resumption, which needs both) -- the model-only load this ADR is actually justified by is a separate function, `load_model_checkpoint`, which never opens the optimizer file. That function, not `load_checkpoint`, is what eval, ADR 0005's attention capture, and cross-variant weight comparisons should call.
